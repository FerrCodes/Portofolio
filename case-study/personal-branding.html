STUDI KASUS

Personal Branding

Landing page modern untuk persiapan memulai karir sebagai freelance web developer.

Tech Stack

Astro
TypeScript
React
Tailwind
Framer Motion

Studi Kasus

1. Masalah

Masalah Awal: Karena ingin mencoba menjadi Freelance dan menjual jasa bisa membuat Web dan Memperbaiki masalah kode, tapi saya belum memiliki Web atau Landing Page untuk menunjukan kepada klien jika saya bisa menunjukan saya bisa membuat Web atau memperbaiki kode dan perfoma Website.
Keputusan Masalah: Saya belum memiliki pengalaman membuat Landing Page yang lebih bagus, modern, dan bahkan belum pernah memakai Tech Stack (Tumpukan Teknologi) yang modern, jadi saya memutuskan mencoba membuat Personal Branding dengan menggunakan Tech Stack yang modern seperti sekarang yaitu Astro, Typescript, React, Tailwind, Framer Motion, Karena saya tahu Tech Stack yang dipakai itu memberikan kesan "Premium" tanpa mengorbankan performa.

2. Pendekatan & Alasan Memilih Tech Stack

2.1 Kebutuhan

Kecepatan & SEO, Interaktivitas, Styling, Hosting, Form Handling

2.2 Pilihan Stack

Astro untuk static site generation, TypeScript untuk type safety, React untuk komponen interaktif, Tailwind untuk styling cepat, dan Framer Motion untuk animasi halus.

2.3 Alasan Utama

• Astro: Static Site Generation (SSG) bawaan membuat website sangat cepat dan ramah SEO – penting agar klien mudah menemukan website di Google.
• React + Framer Motion: Untuk komponen interaktif (marquee draggable, lightbox zoom, mobile menu) – memberikan kesan "premium" tanpa mengorbankan performa.
• Tailwind CSS: Memungkinkan desain brutalis/industrial dengan cepat dan konsisten di semua section.
• Vercel (sementara): Untuk sementara hosting ke Vercel untuk bisa lihat oleh publik atau orang lain.
• Formspree: Tanpa backend, form kontak langsung mengirim email ke saya – solusi paling simpel untuk MVP.

3. Kendala Teknis

• Integrasi Astro + React State: Kesulitan awal saat membuat Hamburger Menu. Script inline di .astro gagal berkomunikasi dengan state React di .tsx karena perbedaan lifecycle hydration. Solusinya: Memindahkan logika toggle sepenuhnya ke dalam React component dan menggunakan global event listener yang robust.
• Responsivitas Tipografi Masif: Headline text-9xl terlihat gagah di desktop tapi hancur/terpotong di mobile. Butuh iterasi berkali-kali menyesuaikan clamp(), line-height, dan padding container agar tetap "bold" tapi aman di semua viewport.
• TypeScript Strictness di file .astro: Error atribut SVG (strokeLinecap vs stroke-linecap) karena perbedaan standar JSX dan HTML native. Ini memaksa kita untuk lebih teliti membedakan konteks file .tsx dan .astro.

4. Solusi

• Modular Component Architecture: Memecah UI menjadi komponen kecil (FadeIn, ProjectCard, MobileMenu, DraggableMarquee). Ini membuat kode maintainable dan reusable.
• Hybrid Contact Strategy: Menggabungkan Formspree (untuk formalitas/email) + WhatsApp Direct Link (untuk konversi cepat). Ini menyelesaikan masalah "friction" klien yang malas isi form panjang.
• Custom Favicon & Meta Tags: Membuat favicon SVG manual dengan gradient biru premium dan melengkapi Open Graph tags. Ini menyelesaikan masalah "first impression" saat link dibagikan di sosmed.

5. Pelajaran yang Didapat

Kontrol Penuh Itu Penting: Sebagai developer, kita harus paham setiap baris kode yang kita tulis. Jangan asal copy-paste solusi AI tanpa mengerti why dan how-nya. Insiden "Header yang diubah-ubah" mengajarkan pentingnya ownership atas kode sendiri.
